1. ပြင်ဆင်ချက်ရဲ့ အနှစ်ချုပ် (Why this matters)
================================================================================

v1 ရဲ့ diagram မှာ "Persistence (Postgres)" ကို Simulation Core ရဲ့ side-module
အဖြစ်ပဲ ထည့်ခဲ့ပေမယ့် boundary က မကျပ်လုံလောက်သေးပါဘူး — Core module တွေက
Drizzle/db client ကို တိုက်ရိုက် import လုပ်ခွင့်ရှိနေရင် "DB မပါဘဲ run/test/replay"
ဆိုတာ မဖြစ်နိုင်တော့ပါဘူး။ ဒါကြောင့် hard rule သတ်မှတ်ပါတယ်:

  >>> `src/sim/**` အောက်က ဖိုင်တွေထဲမှာ `drizzle-orm`, `pg`, `@/db`, `next/*`,
      `react`, `three` — ဘယ်တစ်ခုမှ import လုပ်ခွင့်မရှိပါ။

Core ဟာ pure TypeScript, zero I/O, zero framework dependency module အုပ်စု
ဖြစ်ရမယ်။ Input/Output ကို function parameter/return value ဖြင့်ပဲ ဆက်သွယ်ရမယ်
(WorldState in → WorldState out)။

2. ပြင်ဆင်ပြီး Layered Architecture
================================================================================

MASTER SEED
   |
   v
DETERMINISTIC RULES / RNG STREAMS   (src/sim/core/rng, src/sim/rules)
   |
   v
SIMULATION CORE                      (src/sim/**)
   - pure functions: (WorldState, dt) -> WorldState
   - no DB, no framework, no rendering
   - fully unit-testable in isolation
   |
   v
WORLD STATE                          (in-memory object graph, serializable)
   - single canonical snapshot of the entire world
   - plain JSON-serializable data (no class instances w/ methods, no DB rows)
   |
   v
PERSISTENCE ADAPTER (interface/port)  (src/sim/persistence/PersistencePort.ts)
   - save(state) / load(id) / listSnapshots() / appendHistory()
   - Core depends ONLY on this interface, never on an implementation
   |
   +--> PostgresAdapter   (src/adapters/postgres/*)   -- production storage
   +--> InMemoryAdapter   (src/sim/persistence/memory.ts) -- unit tests, headless runs
   +--> FileAdapter (future) -- local/offline single-player save files
   |
   v
GAME CLIENT(S)                        (outside src/sim/**)
   - Web/Three.js (interim, this sandbox)
   - Godot 4.x (future, primary target)
   - talk to Core only via API layer (Next.js routes) or, later, direct binding

အဓိက အချက်: Persistence Adapter ဟာ Dependency Inversion pattern — Core က
interface (PersistencePort) ကိုသာ သိတယ်၊ Postgres implementation ကို host
application (Next.js API layer) ကနေ inject လုပ်ပေးရမယ်။ ဒါကြောင့် Core ကို
DB လုံးဝမပါဘဲ (InMemoryAdapter ဖြင့်) unit test/headless simulation/deterministic
replay run လို့ရမယ်။

3. WorldState — Serialization Contract
================================================================================

WorldState ဟာ Core ရဲ့ "single source of truth" ဖြစ်ပြီး -

- Plain JSON-serializable object ဖြစ်ရမယ် (Date, Map, Set, class instance မပါ —
  timestamp ကို number/tick count၊ collection ကို array/plain object နဲ့ပဲ
  ကိုယ်စားပြုမယ်)။
- save() = JSON.stringify(worldState) (or structured clone), load() =
  JSON.parse() + schema validation (Zod) — DB API string/BLOB column
  တစ်ခုတည်းနဲ့တောင် ကိုက်ညီနိုင်ရမယ်။
- Version stamped: { contractVersion, seed, tick, ...domainState } —
  deterministic replay verification (hash(state)) အတွက် အသုံးပြုမယ်။
- Postgres schema ဘက်မှာ WorldState ကို normalized relational table
  (chunks, species, npcs...) အဖြစ်ဖြစ်စေ၊ snapshot blob (jsonb) အဖြစ်ဖြစ်စေ
  သိမ်းနိုင်ပေမယ့် ၎င်းက PersistenceAdapter implementation detail ဖြစ်ပြီး
  Core က ဘယ်လိုမှ မသိရပါ။

================================================================================
4. Determinism & Replay Guarantee
================================================================================

replay(seed, initialConditions, tickCount)
  = fold(tick, InitialState(seed, initialConditions), [0..tickCount])

- RNG stream တစ်ခုချင်းစီ (Geography/Climate/.../Event) ကို seed + streamName
  hash ကနေ derive လုပ်မယ်၊ Core state ထဲမှာပဲ RNG internal state ကို ကိုယ်တိုင်
  သိမ်း (external Math.random() လုံးဝမသုံး)။
- tick(state, rngSnapshot) -> newState ဖြစ်ပြီး random draw တိုင်းကို
  state-embedded RNG ကနေပဲ ဆွဲရမယ် — ဒါမှ "Seed + Version + InitialState ->
  same result" ကို အာမခံနိုင်မယ်။
- QA (Team 23) အတွက် golden-hash replay test: seed တူ၊ tick count တူရင်
  final-state hash တူရမယ်ဆိုတဲ့ automated test ကို Phase 1 ကတည်းက ထည့်မယ်။

5. Emergence Philosophy -> Code Structure ဘာသာပြန်ချက်
================================================================================

Rule: Seed -> Rules -> Initial Conditions -> Simulation -> Emergent World -> History

  Seed
    Code: MasterSeed (single number/string)
    Hardcode ခွင့်ပြုတာ: seed value ကိုယ်တိုင်
    Hardcode တားမြစ်တာ: —

  Rules
    Code: src/sim/rules/* — pure function/constant tables (physics constants,
          mutation rate, need-decay formula, biome thresholds)
    Hardcode ခွင့်ပြုတာ: ရုပ်ပိုင်း/ဇီဝဗေဒ ဆက်ဆံရေးနိယာမ
          (e.g. "temperature affects mutation rate")
    Hardcode တားမြစ်တာ: ဘယ် species ဖြစ်လာမယ်ဆိုတာ တိုက်ရိုက်ရေးခြင်း

  Initial Conditions
    Code: WorldGenesisConfig (seed-derived: continent count, starting species
          archetypes, starting population)
    Hardcode ခွင့်ပြုတာ: "world ဒီလို start ဖြစ်မယ်" ဆိုတဲ့ parameter
    Hardcode တားမြစ်တာ: "history ဒီလိုဖြစ်လာမယ်" ဆိုတဲ့ scripted event

  Simulation
    Code: src/sim/**/tick.ts — ecology/evolution/npc/society tick functions
    Hardcode ခွင့်ပြုတာ: —
    Hardcode တားမြစ်တာ: ဘယ်တိုက်ခိုက်မှု၊ ဘယ် discovery ဖြစ်မယ်ဆိုတာ scripted logic

  Emergent World
    Code: Runtime WorldState (creature populations, settlements, technology
          levels) — generated, never authored
    Hardcode ခွင့်ပြုတာ: —
    Hardcode တားမြစ်တာ: —

  History
    Code: HistoryEvent[] — simulation ကိုယ်တိုင် append လုပ်တဲ့ log
          (e.g. "tick 4021: Species X went extinct due to resource
          competition in Chunk 7,3")
    Hardcode ခွင့်ပြုတာ: —
    Hardcode တားမြစ်တာ: Pre-written narrative event

Code review checklist (Team 00 enforce မယ်): PR/diff ထဲမှာ
if (npcName === "..."), hardcoded city name, scripted war/discovery timeline
စသည်ဖြစ်ရင် reject။

6. Revised Module Boundaries
================================================================================

src/
  sim/                        <- PURE CORE (no DB, no Next.js, no React, no
                                   Three.js, no Godot)
    core/
      rng.ts                   deterministic RNG (mulberry32 + stream hashing)
      seed.ts                   MasterSeed -> sub-stream derivation
      tick.ts                   top-level simulation step orchestrator
      worldState.ts             WorldState type + factory + hashing
                                 (replay verification)
    rules/                     constant tables & pure formulas (physics,
                                 biology, social)

    worldgen/                  geography, climate, geology generators
                                 (seed -> ChunkData)
    materials/                  material/object property + transformation graph
    biology/                    genome, phenotype
    evolution/                   selection, mutation, speciation, extinction
    ecology/                     population dynamics, resource competition
    npc/                         needs, perception, memory, personality,
                                  decision-making
    society/                     settlement emergence, economy, culture,
                                  technology, law
    history/                     append-only event chronicle
    persistence/
      PersistencePort.ts        interface: save/load/listSnapshots/appendHistory
      memory.ts                  InMemoryAdapter (for tests & headless runs)
    test/                        pure unit tests (no DB) — determinism/replay
                                  suite

  adapters/                    <- IMPURE, framework-specific glue (outside sim/)
    postgres/
      PostgresAdapter.ts        implements PersistencePort using Drizzle
      mappers/                   WorldState <-> relational rows/jsonb mapping

  db/
    schema.ts                   Drizzle tables (storage shape only, not domain
                                 model)
    index.ts                     (existing db client)

  app/
    api/
      health/
      sim/
        world/                  POST create/load world (uses PostgresAdapter)
        tick/                    POST advance N ticks
        state/[worldId]/        GET WorldState snapshot (or delta)
        history/[worldId]/       GET event log
    world/                       interim R3F web viewer page (client-web)

  client-web/                  thin rendering-only components (React Three

လုပ်ခွင့် လုံးဝမရှိ။ ဆန့်ကျင်ဘက် (adapters -> sim) ကတော့ ခွင့်ပြုတယ်
(adapter ကနေ core type/interface ကို implement လုပ်ရမှာမို့)။

7. Persistence Adapter — Contract Sketch (design only, code မရေးသေးပါ)
================================================================================

// src/sim/persistence/PersistencePort.ts  (pure interface, part of Core)
interface PersistencePort {
  saveSnapshot(worldId: string, state: WorldState): Promise<void>;
  loadSnapshot(worldId: string): Promise<WorldState | null>;
  listWorlds(): Promise<WorldSummary[]>;
  appendHistoryEvents(worldId: string, events: HistoryEvent[]): Promise<void>;
  loadHistory(worldId: string, range?: TickRange): Promise<HistoryEvent[]>;
}

- InMemoryAdapter — Map<string, WorldState> ဖြင့် implement (Phase 1 unit
  test/replay test အတွက်)။
- PostgresAdapter — Drizzle ဖြင့် implement၊ src/adapters/postgres/ အောက်မှာသာ
  ရှိမယ်၊ Next.js API route ကနေပဲ construct/inject လုပ်မယ်။
- Core ရဲ့ tick()/generateWorld() function တွေက PersistencePort ကို parameter
  အဖြစ်လက်ခံခြင်းမျိုးမပြု — Core ဟာ persistence ကို လုံးဝမသိပါ။ Persistence
  ကို orchestration layer (API route level) ကပဲ "run tick -> get new state ->
  adapter.save(state)" ဆိုပြီး ခေါ်သုံးရမယ်။ ဒါက Core ကို 100% I/O-free
  ဖြစ်စေတယ်။

8. Data Flow (Revised)
================================================================================

[Cold start / New World]
MasterSeed -> sim/core/seed.ts -> RNG sub-streams
           -> sim/worldgen (pure) -> initial WorldState (in memory)
           -> (orchestration layer) -> PersistencePort.saveSnapshot()

[Simulation Tick]
PersistencePort.loadSnapshot() -> WorldState (plain object, no DB dependency
                                    once loaded)
           -> sim/core/tick.ts(state, N) -> newState + HistoryEvent[]
              (pure, DB-free)
           -> (orchestration layer) -> PersistencePort.saveSnapshot(newState)
                                    -> PersistencePort.appendHistoryEvents(events)

[Client Read]
Client (Web or Godot) -> GET /api/sim/state/:worldId
     -> API route -> PersistencePort.loadSnapshot() -> JSON response
     -> Client renders

[Player Action]
Client -> POST /api/sim/command -> API route validates -> loads state
     -> sim/core applies command as a rule-bound action (pure) -> newState
     -> PersistencePort.saveSnapshot(newState)

[Offline / Headless / Test]
Test runner -> sim/worldgen + sim/core/tick directly, using InMemoryAdapter
     or no adapter at all
     -> no Postgres, no Next.js required at all

9. Testing Strategy (Revised — DB-independent by design)
================================================================================

- Unit tests (src/sim/test/): worldgen determinism, RNG stream isolation,
  genetics/evolution formulas, NPC decision functions — DB မပါဘဲ
  `node --test` or `vitest` (pure Node, no server) ဖြင့် run မယ်။
- Replay/Determinism test: same seed + same tick count -> identical
  WorldState hash — regression suite အဖြစ် CI equivalent (bash validation
  step) ထဲမှာ ထည့်မယ်။
- Integration tests: PostgresAdapter ကိုသာ သီးခြား စမ်းမယ် (mapping
  correctness), Core logic ကို ထပ်မစမ်း (Core ကို unit test ကတည်းက
  အပြည့်စမ်းပြီးသားမို့)။
- ဒီ project ရဲ့ final validation sequence (typegen, tsc, next build,
  build_and_start) ကို ဒီအတိုင်း ဆက်လက် လိုက်နာမယ်၊ ဒါ့အပြင် Core-only unit
  test script တစ်ခု (npm run test:sim သဖွယ်) ကို Phase 1 မှာ ထပ်ထည့်ဖို့
  အစီအစဉ်ရှိပါတယ်။

  (geography/climate/geology realism, material/object transformation graph)

Phase 4 — Biology/Genetics/Evolution/Ecology loops

Phase 5 — NPC Intelligence & Life
  (needs/goals/memory/decision loop, headless-testable)

  — thin renderer consuming API only, stylized-realistic vertical slice

  — chunk LOD tiers, simulation tiers, save/export/import, full replay

11. Risks (Updated)
================================================================================

- Discipline risk: Core purity ကို code review level မှာ တင်းကျပ်စွာ enforce
  ဖို့လိုမယ် (accidental `import { db }` creeping into sim/**) — mitigation:
  lint rule/import-boundary check (later: eslint no-restricted-imports rule
  scoped to src/sim/**) ကို Phase 1 အတွင်း ထည့်ဖို့ စီစဉ်ပါတယ်။
- Serialization overhead: WorldState ကြီးလာရင် full-snapshot JSON save/load
  က slow ဖြစ်နိုင် — later phase မှာ delta-save/event-sourcing ဖြင့် optimize
  လုပ်ရန် leave ထားမယ် (v1 architecture အတိုင်း roadmap ထဲမှာပါပြီးသား)။
- Two-client drift — v1 အတိုင်း risk ရှိနေဆဲ၊ versioned contract + Zod ဖြင့်
  mitigate။

12. Final Statement
================================================================================

ဒီ refinement အရ Simulation Core ဟာ PostgreSQL, Next.js, React, Three.js,
Godot — အားလုံးမပါဘဲ standalone run/test/replay လုပ်နိုင်တဲ့ pure TypeScript
module ဖြစ်လာမယ်။ Postgres ကို Persistence Adapter (implementation detail)
တစ်ခုအဖြစ်သာ ဆက်ဆံမယ်။ ဒီဇိုင်းက "Seed -> Rules -> Initial Conditions ->
Simulation -> Emergent World -> History" ဆိုတဲ့ core philosophy ကို
code-level constraint (import boundary, pure function signature,
hardcode-forbidding review rule) ဖြင့် တင်းကျပ်စွာ အာမခံပေးပါတယ်။

Implementation ကို မစပါသေးဘူး — Team 01 Foundation ကို ဒီ revised
architecture နဲ့ စလုပ်ဖို့ approval စောင့်ပါမယ်။
